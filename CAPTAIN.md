**Inference is the ingredient that makes the whole thing buildable, and the pairing rather than the inference is what makes it usable.** Terminal accessibility is an empty category because rule-based structure recognition over arbitrary terminal programs does not work: the idioms are a catalogue with no end, `ls -la` against `top` against `df` against `git log --oneline`, and this voyage walked into exactly that with column detection. Inference covers what a rule set cannot finish. Inference alone would be a guessing machine and nobody tests against a guess.

**The division that makes it trustworthy: inference for coverage, determinism for trust.** The grid determines what it determines, cursor, attributes, geometry and exit. Inference proposes what convention decides, which idiom this is, where the columns fall, what a region is called. The screen refuses whatever inference cannot back, and replay invokes no model at all. Neither half suffices alone: a rule set cannot reach arbitrary programs, and a model cannot be trusted to write tests. **Together they reach arbitrary programs and still produce artifacts that replay deterministically, which is the combination that did not exist to be built before.**

**It also answers the outside review's sharpest objection.** A maintained idiom catalogue is what rules produce when they must cover everything, and the answer is not a better catalogue: it is to stop maintaining one wherever inference generalises and a deterministic pass refutes.

## Inference proposes structure, reconstruction proves it. Operator 2026-07-27, and it amends a standing rule.

**Why a rule set cannot finish the job.** Column shapes are an unbounded idiom catalogue: `ls -la` carries no header, `top` carries one whose boundaries merge because a right-aligned column sits beside a left-aligned one, `df` differs again, `git log --oneline` has neither header nor alignment. Every mechanical rule so far has needed one more special case, which is exactly what the outside review warned the whole model risks becoming. **Inference generalises where rules accumulate exceptions.**

**The safety property is stronger here than for names, and that is the whole argument.** A proposed column layout is verifiable by **reconstruction**: split each row at the proposed boundaries, rejoin, and the original line must return byte for byte; every row must yield the same cell count; no cell may straddle a boundary. That is arithmetic over the character grid rather than judgment. The name rule's check is weaker, being only that the screen carries the text somewhere. **So a model proposing structure is better guarded than a model proposing names, which is the reverse of what the standing rule assumed.**

**Replay is untouched.** The plan records the boundaries and replay applies them mechanically, so no model runs at replay time and determinism holds exactly as before.

**This amends "the engine proposes names, never roles", and the amendment should be explicit rather than allowed to slide.** That rule existed to stop a model inventing structure nobody could check. Reconstruction is the check that did not exist when it was written. The amended form: **inference may propose any structure a deterministic pass can refute, and may never propose a structure it cannot.** Roles that no arithmetic can confirm stay the deterministic builder's alone.

## The matrix idea. Discovery only, 2026-07-27. Nothing authored, nothing binding.

**Tinman gets no matrix noun at all. Superseded 2026-07-27 by the operator's observation that promptfoo or similar will likely be the thing running Tinman.** Captain coined "campaign", then argued its way to "matrix" on legibility, and both were answers to a question that belongs to somebody else's tool. Read from the promptfoo docs rather than recalled: `providers` is the matrix, `evaluateOptions.repeat` is the repetition, `assert` is the expectation, and results are reported per cell of test times prompt times provider. All of it exists. Building `matrix:` into a Tinman plan would reinvent an eval harness, which is exactly what the anti-NIH rule forbids, and it would also break the operator's likely real workflow by assuming Tinman is the outer loop.

**The division of labour that replaces it.** The harness owns the matrix, the repetition, the assertions, the aggregation and the report. Tinman owns what no harness can do: drive a real coding agent in a PTY inside a sandbox, proxy and record its network, read the screen as a semantic model, and hand back observations. **The framing worth keeping: Tinman makes a coding agent addressable as a provider.** promptfoo evaluates prompts against model APIs; nobody drives a real agent program and measures what it did. That is the whole contribution and it is upstream of any matrix.

**The interface is already specified for us, which is the anti-NIH rule paying out.** A promptfoo custom provider implements `id()` and `callApi()` and returns `{ output, error, tokenUsage: { total, prompt, completion }, cost, cached, metadata }`, with token usage and latency recognised and surfaced as metrics. Non-JS subjects are supported through script, HTTP and Python or Go provider forms, so `tinman driver` and its JSON-RPC protocol are already the right shape and need no new surface. Note what the proxy buys here: a normal provider reports the token counts its SDK hands it, while Tinman reports what actually crossed the wire, which is a stronger number than the harness gets from anything else plugged into it.

**The eval and observability landscape is inspiration, not a roadmap. Operator, 2026-07-27.** Take ideas, conventions and inventions from it, and make Tinman usable by those tools' users, without bloating Tinman. Concretely this forbids: a per-vendor adapter or plugin for any of them, a vendor SDK as a dependency, a feature Tinman grows only because a platform expects it, and any integration that assumes Tinman is the outer loop. Nineteen tools were studied down to **two surfaces**, and two is the whole permitted footprint: Tinman is **driven** as a subject, and Tinman **emits** observations in a standard shape. Anything a specific vendor needs beyond those two belongs in that vendor's ecosystem, written by whoever wants it, not in this crate.

**What the study found, read from docs rather than recalled.** The observability platforms converged on OpenTelemetry: Phoenix is OTel-native and both emits and accepts OTLP with `gen_ai.*`, Langfuse ingests OTel spans, MLflow's tracing is OTel-native with GenAI semantic conventions, and Laminar, Langfuse, LangSmith and Phoenix are interchangeable from an ingestion standpoint under standard instrumentation. That collapses roughly eight of the nineteen into one emission. The eval harnesses take Tinman as a subject, and promptfoo showed the shape: an identifier, a call, and a response carrying `output`, `tokenUsage` and metadata, with script and HTTP forms for non-JS subjects, which `tinman driver` already satisfies.

**Two gaps, both unresolved and neither guessed at.** The OTel GenAI semantic-convention page has moved to its own repository and the old URL only redirects, so the stability levels are unread. And there are two competing attribute vocabularies, OpenTelemetry's `gen_ai.*` and Arize's OpenInference, with Laminar and Langfuse accepting the latter over the same OTLP exporter. The wire protocol is settled; the attribute vocabulary is not.

**Weight, counted in a throwaway crate so the tree was untouched.** Tinman today locks 438 packages. `opentelemetry-semantic-conventions` **alone is 1 package with zero dependencies**. **The earlier reasoning, kept only as the record of how it was decided.** Not the exporter, not the SDK, and not even the zero-dependency semconv crate. **What base Tinman owes instead, and it is the whole of the work.** Not an exporter: a complete, structured observation stream. **The proxy is the instrument, and the operator widened it into a control surface.** The sandbox denies network, so Tinman already stands between the agent and its provider. - **It returns determinism.** A proxy that records can serve the exchange back, so replaying an agent session invokes no model and touches no network. - **It takes the credential out of the sandbox.** The proxy holds the key and the agent authenticates to Tinman, so an untrusted agent never sees it. Same argument as the workspace overlay, one layer down.

**Playwright answers three of the four pieces. Read from the docs, not recalled.**

- **HAR is the cassette format.** `routeFromHAR` with `update: true` records and `update: false` replays. Matching is strict on URL, method and POST payload, which is exactly right for model calls. - **Projects are the matrix.** `projects: [chromium, firefox, webkit]` is structurally `[pi, opencode, claude]`: one suite, per-project options and retries, per-project reporting, and a flag to select one. - **Trace viewer is the model for the transcript work.** Tinman's version is richer, because a TOM snapshot is semantic where a DOM screenshot is not.

**The open question, unanswered.** Does a matrix hand back a report, or a plan carrying rate expectations such as "the yoink skill is used in at least 8 of 10 runs against opencode", which reddens the day a model update moves the answer? The `inspect` ruling is the precedent: an explainer tells the operator what happened and is believed or not, while a probe writes a plan they commit and watch go red. ## The false-green pattern. The most expensive thing this project has learned.

Every instance was green while asserting nothing. **The test: when a scenario goes green early and cheaply, ask what it would take to make it red. If nothing would, the scenario is the defect.**

The older ones, in brief: a perturbation discharged by deleting its line; a `menu` role the deterministic pass already produced; a launch answering `ok:true` before the program started; a recorded plan carrying no expectation; two activation scenarios asserting text the fixture drew anyway; a scantling that is valid JSON and an invalid schema; a `Given` that seeded nothing, leaving its `Then` asserting against ambient state.

The ones still worth reading:

- **The gplint glob.** `features/**/*.feature` matches zero files, because `**` must consume at least one directory segment and `features/` is flat. It exits 0 having linted nothing. Working values are `features/**` and `features/*.feature`.
- **A plank string shared across six seams.** `@planks("a process is prepared and launched")` is carried by `process.rs`, `sandbox.rs` three times, `bwrap.rs` and `pty.rs`. The string join is green no matter which of the six is dead.
- **An optional schema property is an attestation that cannot fail.** Read the `required` list, not the property list, when asking whether an attestation binds. This is why `cursor` is required in `assistant-ui.schema.json` while it is optional in `tom.schema.json`.
- **A schema can promise a capability production silently discards.** `harness-plan.schema.json` declared `cwd` on a `run:` step while `RunForm::Full` had no such field, and serde dropped the key without a word.
- **A `required` property proves a field exists. Nothing proves it is read.** Crew added the field, left it `None` everywhere, read it nowhere, and threaded a sidecar anyway. Closed by `requiredReferences` in `pty-sandbox-boundary.json`.
- **`tinman replay` was declared and did nothing**, swallowed by a wildcard match arm. **A wildcard match arm is the production form of a glob that reads nothing.** Closed by `command-dispatch-completeness.json`.
- **An absence assertion disarmed by a change to the asset it names.** Captain grew an asset from one line to two and a contiguous-string absence assertion could never fail again. **Absence assertions are the ones that go quiet, because nothing about their output changes when they stop testing.**
- **A focused run against a scenario name that no longer exists selects zero scenarios and exits green.** **A focused run reporting `0 scenarios` is a failed selection, never a pass.** Voyage 10's watchbill was generated by extracting scenario names from the feature files rather than typed, for this reason.
- **A refusal scenario green because the command does not exist.** `completions refuses a shell it cannot emit for` passes today: `tinman completions klingon` exits non-zero because `completions` is not a command at all, so the scenario reports complete while asserting nothing about a refused shell. QM caught it and named it incidental. **Re-run it once the command exists**, or it is green through the whole voyage that builds the thing it claims to test.
- **`mandoc -T lint -W error` exits 0 on an empty file.** Captain hit this live: `tinman man` did not exist, the redirect wrote zero bytes, and the lint reported clean. A validity check with no non-empty floor passes hardest on nothing at all. Closed by `And the emitted page is not empty`.
- **An isolation assertion whose target never reached for the secret.** `record launches its target inside the sandbox` asserted a recorded snapshot did not carry `TINMAN_SECRET` while the fixture never tried to print it. Green for the whole time record ran unsandboxed. Rewritten on voyage 10 with the target printing a marker beside its attempt.

- **A broad sweep is weaker evidence than a narrow one for a race, and it feels stronger, which is what makes it expensive.** 2026-08-01. A process-wide global made two sandboxes bridge to the same proxy. `broad-sandbox` went green **four times**, because it diluted the two racing scenarios among a hundred and rarely interleaved them; the per-feature run that concentrated them reproduced the fault **three times out of three**. A mate in between reran to green and filed it as environment flake. **Two of three signals said fine and the concentrated one was right.** The instinct that a bigger run is a stronger check is exactly backwards here: for an interaction between two named scenarios, every unrelated scenario in the run is noise reducing the chance the interleaving ever happens. **Match the run shape to the question. A green from the wrong shape is not evidence about the thing asked.**
- **A support edit's blast radius is the tier it serves, never the scenarios that happened to run.** Same voyage. QM changed one helper in verification support and said plainly that its twelve focused greens did not cover three call sites the change touched, then ran both sweeps rather than let the count imply coverage. Boatswain then found a **third** tier selected by the same reasoning and swept `@inference` too, at real cost per call. A focused green over a subset never discharges a support edit, and a role that stops at the tiers it happened to think of has stopped one tier short.

## Design decisions that bind (user-confirmed)

- **The assistant never gains capabilities. Tinman gains subcommands, and the assistant proposes them.** "Help me build a fixture" is not the assistant writing files; it is Tinman growing `tinman fixture new`, proposed and confirmed through `parse_command_line` like every other action. The blast radius of a confused model stays the enumerable set of subcommands, and every capability remains usable by a human with no model in the loop.
- **One surface, three consumers: a human at a terminal, Tinman's own assistant, and someone else's coding agent.** Nothing is assistant-only, so discoverability is the whole game. `SKILL.md` is the one prose source, read directly by agents and rendered for humans. `mandown` was declined: rendering the skill as roff puts it on the drift-prone side.
- **The skill and the man page are not one document.** A man page is exhaustive reference, a skill is teaching material. What unifies them is their sources: the CLI surface from clap, the concepts from prose.
- **`--help` is ground truth** for a program under inspection, from the binary being tested, at the installed version, inside the sandbox. **`man` opportunistically**, absent from a minimal bwrap sandbox. **tldr, including `tlrc`, as hints only**, never as the basis for an assertion, on the drift argument alone; the network objection was wrong and the user caught it, since network is denied to the target and not to Tinman. Voyage 10 authored the consuming half against inference naming, where a stale page costs a worse suggestion the deterministic pass then refuses. The `--help` ground-truth half is still unauthored and rides with the `inspect` stream-versus-screen answer Captain owes.
- **Every driver call except `launch` names its session, and an omitted session is an error rather than a default.** A driver holds several sessions at once, so defaulting is a guess.
- **Tinman is a driver, not only a CLI.** `tinman driver` speaks newline-delimited JSON-RPC 2.0. The YAML plan stays canonical for recorded flows. The protocol is RPC, not a second test format.
- **TOM is the DOM equivalent and inference is codegen.** The deterministic builder is the spine and produces every addressable role. The LLM engine is a second producer of the same shape, capture time only, proposing **names, never roles**.
- **Resolution and confirmation are two operations.** Resolution answers what a locator matches and reports ambiguity as ambiguity. Confirmation runs at capture time only.
- **Terminal size is a property of the run, never of the plan.**
- **Plan YAML grows with the test.** Shorthand removes typing, never adds capability, never weakens a default. An omitted `sandbox:` block means secure defaults, not no sandbox.
- **`home: fixture` and `env.from: fixture` are struck.** `mounts` is the live provision for reaching a tree outside the bound set.
- **The `@inference` tier asserts our seam, never the model's compliance.** Shaping the request is not validating the response.
- **Help text is an asset, not a scenario.** Copy lives in `assets/help/`.
- **Inference: any OpenAI-compatible provider, OpenRouter the default.** `TINMAN_API_KEY`, `TINMAN_BASE_URL`, `TINMAN_MODEL`. Environment wins over `.env`. The credential is vendor-neutral by name so the default is never lock-in.
- **Tier placement.** `@sandbox` marks scenarios that need a real sandbox to run at all, which after voyage 10 includes every `record` and `inspect` scenario that launches. `@inference` is real paid calls, never on the inner loop. Retag a scenario rather than weaken a tier policy.
- **Emulator is `alacritty_terminal` 0.26.0.** `vt100` was unmaintained and failed cell addressing and reverse video. `wezterm-term` is better and disqualified: not on crates.io, and we publish. `alacritty_terminal` is 0.x and breaks across releases; budget for that.
- **Scantlings go into the assistant context, features do not.** Measured: `features/` 94794 chars, all scantlings 37960, the six user-facing ones 22087, `SKILL.md` 6025. The argument that decides it: a scantling cannot drift, because a `@contract` scenario pins it, while the skill can and did.

## Three doctrine gaps worth raising upstream, found 2026-07-28

**Red-first assumes a dry-run, and says nothing where there is none.** The Verification policy names static discovery as its own shape, the `discover` dry-run listing unimplemented steps and executing nothing. Where a runner offers none, as cucumber-rs does not, every step a role writes must compile at once, and doctrine offers no replacement shape. **This is the load-bearing gap; the other two are consequences.**

**Doctrine governs hand-offs and never mentions transient state within a turn.** A role required to produce a failure it can only produce by breaking the build finds no text saying that is permitted, and correctly declines to invent permission.

**Nothing states that a compile failure naming an absent seam is a production-code failure.** It plainly is, and Crew's dispatch condition is met by it, but a role reading the text conservatively concludes there is no legal ordering.

**Captain's own error here is worth keeping.** Captain asserted that doctrine says a compile error is not a failing target. It says no such thing; the claim was invented and then reasoned from. The operator caught it by asking where it says that. **A rule cited from memory is a claim, and the whole session's discipline says a claim is not evidence until a command answers it.** Checked against the skill text, the only rule is that Crew is dispatched for production-code failures.

Local guidance so this project sails as is now lives in `AGENTS.md` beside the `discover: none` note.

## A third doctrine gap, found by Boatswain 2026-07-31

**`AGENTS.md` is a harbour-only write scope and the practice has outgrown it.** The Write scopes Article gives Shipwright that file during harbour only, yet it rode this at-sea commit and the eight most recent commits touching it. The practice looks settled and the Article has not caught up.
